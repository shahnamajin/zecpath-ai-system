# Day 23 – Transcript Data Architecture

## Objective

Define a structured architecture for converting voice-based HR screening conversations into AI-processable transcript data.

---

## Voice Transcript Schema

Every screening session contains:

- Transcript ID
- Candidate ID
- Job ID
- Session ID
- Language
- Start timestamp
- End timestamp
- Conversation metadata
- Individual screening interactions

---

## Metadata Standards

### Candidate ID

Format:

CAND_<unique_number>

Example:

CAND_1001

Used to uniquely identify a candidate.

---

### Job ID

Format:

JOB_<unique_number>

Example:

JOB_2001

Used to associate the screening session with a specific job.

---

### Question ID

Question IDs are inherited from the Day 22 HR screening question dataset.

Example:

HR_INT_001

HR_SKILL_PY_001

This creates a direct relationship between the HR question bank and transcript data.

---

### Timestamp

All transcript interactions contain timestamps.

Recommended format:

ISO 8601

Example:

2026-09-15T10:00:25Z

Timestamps allow the system to reconstruct the conversation sequence.

---

### Confidence Level

Speech-to-text confidence is represented using a value between 0 and 1.

Example:

0.96

Interpretation:

0.90–1.00 = High confidence

0.70–0.89 = Medium confidence

Below 0.70 = Low confidence

Low-confidence responses can be flagged for additional processing.

---

## Transcript Normalization Rules

Raw speech-to-text data should be normalized before AI processing.

Rules include:

1. Remove unnecessary leading and trailing whitespace.
2. Normalize multiple spaces.
3. Normalize repeated punctuation.
4. Remove common speech filler words when appropriate.
5. Preserve the original meaning of the candidate's response.
6. Do not modify technical terms unnecessarily.
7. Preserve important numbers, dates and names.
8. Keep speaker identity.
9. Preserve question-to-answer relationships.
10. Preserve timestamps.
11. Keep the original transcript available for audit purposes.

---

## Speaker Identification

Two primary speakers are supported:

- `ai`
- `candidate`

The AI speaker represents questions or prompts generated by the screening system.

The candidate speaker represents the candidate's spoken response.

---

## Screening Interaction Structure

Each interaction contains:

- Interaction ID
- Candidate ID
- Job ID
- Question ID
- Speaker
- Timestamp
- Transcript text
- Confidence level
- Sequence number

## Database Design

The future database can use the following logical entities:

### Candidates

Stores candidate information.

### Jobs

Stores job information.

### Screening Sessions

Stores each screening session.

### Screening Questions

References the Day 22 HR question dataset.

### Transcript Interactions

Stores individual AI and candidate conversation turns.

### Screening Evaluations

Stores AI evaluation results for candidate responses.

## Privacy and Audit Considerations

Transcript data should be treated as sensitive application data.

The system should:

- Use unique internal IDs.
- Avoid unnecessary personal information in transcript metadata.
- Restrict transcript access.
- Maintain original transcripts for auditing where required.
- Store model/version information for reproducibility.
- Maintain timestamps for traceability.
